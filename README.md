# Limit Order Book (LOB)

A C++23 implementation of a limit order book and price-time-priority matching engine. This project is being developed to explore exchange mechanics, data structures, and performance-oriented C++ programming.

## Features

- **Limit order matching:** incoming orders execute against compatible resting orders.
- **Price-time priority:** the best available price is matched first; orders at the same price are matched in FIFO order.
- **Partial fills:** orders can be partially executed, with any remaining quantity rests in the book.
- **Multi-level matching:** a single incoming order can execute against multiple resting orders at different price levels.
- **Order cancellation:** resting orders can be cancelled by order ID.
- **Trade records:** each submission returns the executions generated by that order, including buyer ID, seller ID, execution price, and quantity.
- **Trade recorder:** accumulates trade records across submissions.
- **Book queries:** retrieve the best bid, best ask, bid-ask spread, and aggregate quantity at a given price.
- **Automated tests:** GoogleTest coverage for matching, cancellation, book queries, and trade recording.

## Technical Overview

### Language and tools

- C++23
- CMake
- GoogleTest
- Standard Template Library (STL)

### Data structures

| Component | Implementation | Purpose |
|---|---|---|
| Bid side | `std::map` with descending price order | Retrieves the highest bid first |
| Ask side | `std::map` with ascending price order | Retrieves the lowest ask first |
| Price level | `std::list<Order>` | Maintains FIFO order at each price |
| Order index | `std::unordered_map` | Locates resting orders for cancellation |
| Trade history | `std::vector<Trade>` in `TradeRecorder` | Accumulates executions |

The order book maintains aggregate quantity at each price level. The order index stores iterators to resting orders, allowing cancellation without scanning the entire book.

### Matching rules

An incoming buy order matches resting sell orders when the ask price is less than or equal to its limit price. An incoming sell order matches resting buy orders when the bid price is greater than or equal to its limit price.

Executions occur at the resting order's price. Matching continues until the incoming order is fully filled or no compatible resting orders remain. Any unfilled quantity is added to the book.

## Build

Requirements:
- A C++23-compatible compiler
- CMake 3.20 or newer
- Git and network access on the first configuration if GoogleTest must be downloaded

Configure and build:

```bash
cmake -S . -B build
cmake --build build
```

Run the test suite:

```bash
ctest --test-dir build --output-on-failure
```

GoogleTest is fetched through CMake FetchContent when testing is enabled.

## Example Usage

```cpp
#include "order_book.hpp"
#include "trade_recorder.hpp"

OrderBook book;
TradeRecorder recorder;

// Add a resting sell order.
auto trades = book.submit(Order{
    1, Side::Sell, 101, 10
});
recorder.record(trades);

// Submit a buy order that partially fills the resting ask.
trades = book.submit(Order{
    2, Side::Buy, 101, 4
});
recorder.record(trades);

// Inspect the executions.
for (const auto& trade : recorder.history()) {
    // Access buy_order_id, sell_order_id,
    // price, and quantity.
}
```

After the second submission, the recorder contains one trade: buy order 2 bought 4 units from sell order 1 at price 101. The remaining 6 units of sell order 1 stay in the book.

## Current Scope

This is an educational matching-engine prototype, not a production exchange. It currently focuses on in-memory order management and matching.

It does not yet implement networking, market-data distribution, persistence, concurrent order processing, exchange protocols, or production-grade recovery and risk controls.
